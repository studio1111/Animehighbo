# Animehighbo

ربات زمان‌بندی‌شدهٔ **Animehighbo** برای تلگرام: پایش فیدهای مجاز، دریافت فایل‌هایی که اجازهٔ دانلود و بازنشرشان را دارید، جلوگیری از انتشار تکراری و ارسال فایل به کانال تلگرام.

## وضعیت فعلی

## وضعیت آرشیو قسمت‌ها

قابلیت صف آرشیو ترتیبی در شاخهٔ توسعه‌ای `feature/episode-archive-backfill` در حال آماده‌سازی است و هنوز به `main` ادغام نشده است. این قابلیت با انتشار عادی RSS یکی نیست: فید SubsPlease فقط انتشارهای اخیر را می‌دهد و برای بازسازی آرشیو تاریخی از قسمت ۱ تا آخرین قسمت، به فهرست منابع مجاز و ترتیب قسمت‌ها نیاز است.

- فایل صف: `data/archive_manifest.json`
- هر رکورد باید عنوان مشخصِ یک قسمت، نشانی منبع و `authorized_for_redistribution: true` داشته باشد.
- قسمت‌های batch، شمارهٔ قسمت نامشخص و نشانی تکراری رد می‌شوند.
- صف باید به ترتیب انتشار مرتب باشد؛ پردازش قسمت بعدی نباید پیش از تکمیل قسمت فعلی آغاز شود.
- **در وضعیت فعلی، manifest خالی است (`[]`). بنابراین آرشیو تاریخی هنوز دانلود، پردازش یا به تلگرام منتشر نشده و نباید حالت آرشیو فعال شود.**
- اطلاعات AniList برای عنوان، پوستر و فراداده مفید است، اما خودش فایل ویدیویی یا مجوز بازنشر فراهم نمی‌کند. فهرست منبع باید به فایل‌هایی اشاره کند که مجوز دانلود، پردازش و انتشار آن‌ها وجود دارد.

هدف نهایی انتشار هر قسمت این است: یک پوستر با فراداده و خلاصهٔ فارسی، سپس سه فایل قابل پخش 1080p، 720p و 480p با کدک H.265 در MKV و زیرنویس انگلیسی و فارسیِ روان و همگام. انتشار باید پس از اعتبارسنجی واقعی فایل‌ها و تأیید ارسال موفق ادامه یابد. سبزشدن CI به‌تنهایی به معنی آماده‌شدن آرشیو یا ارسال موفق به کانال نیست.


انتشار فقط از مسیر ناشر اصلی انجام می‌شود؛ گردش‌کار مستقلِ پوستر-only حذف شده تا فیدهای کیفیت مختلف نتوانند برای یک قسمت چند پوستر جداگانه بسازند. هر گروه قسمت ابتدا یک پوستر با مشخصات کامل و خلاصهٔ فارسیِ پنهان‌شونده منتشر می‌کند؛ سپس سه خروجی 1080p، 720p و 480p به‌صورت پاسخ به همان پیام ارسال می‌شوند. اگر هر مرحله شکست بخورد، پردازش انیمهٔ بعدی متوقف می‌شود و گروه ناقص در اجرای بعدی ادامه پیدا می‌کند.

## قابلیت‌ها

- بررسی فیدها از طریق ناشر اصلی با GitHub Actions و اجرای دستی
- یک پوستر برای هر قسمت با نام انگلیسی و فارسی، شمارهٔ قسمت، فصل/سال، تعداد قسمت‌ها، ژانر، قالب، وضعیت پخش، امتیاز و استودیو در صورت دسترس بودن؛ خلاصهٔ فارسی روان و محاوره‌ای داخل بخش پنهان‌شونده است.
- ارسال فایل‌های همان قسمت به‌صورت پاسخ به پیام پوستر و به ترتیب 1080p، 720p و 480p؛ انیمهٔ بعدی تا تکمیل هر سه کیفیت شروع نمی‌شود
- حالت لینک‌محور برای انتشار پوستر، نام انیمه، شمارهٔ قسمتِ قابل استخراج و دکمهٔ لینک تماشا
- دریافت پوستر از RSS/Atom یا فراداده‌های Open Graph صفحهٔ قسمت، با سقف ۸ مگابایت
- خواندن RSS/Atom از منابع مجاز
- کنترل شناسه و هش فایل برای جلوگیری از تکرار
- دریافت فایل مستقیم فقط از دامنه‌های HTTPS مجاز پیکربندی‌شده
- کنترل حجم و امضای ابتدایی فایل پیش از ارسال
- تبدیل اختیاری ویدئو به H.265/HEVC در MKV با کنترل CRF و preset، بررسی مدت‌زمان/کدک/ترک‌ها و امکان حک‌کردن زیرنویس فارسی زرد با حاشیهٔ مشکی نازک
- خط آخر کپشن پوستر بعد از خلاصهٔ فارسی دقیقاً `@Animehighbo` است. نام فایل خروجی فقط شامل نام انیمه، کیفیت و شناسهٔ کانال است؛ مانند `PSYREN 1080p @Animehighbo.mkv`
- ارسال MP4 با Telegram Bot API به روش sendVideo و MKV با روش sendDocument
- استخراج زیرنویس انگلیسیِ متنی، ترجمه با Gemini در صورت تنظیم `GEMINI_API_KEY` (و در غیر این صورت مترجم آفلاین Argos)، و نگهداری هر دو ترک در MKV
- پشتیبانی از نشانی قابل تنظیم Telegram Bot API برای سرور محلی
- نگهداری وضعیت انتشار برای جلوگیری از تکرار در اجراهای بعدی
- آزمون‌های خودکار

## راه‌اندازی

1. با BotFather یک ربات تلگرام بساز.
2. در مخزن GitHub به Settings → Secrets and variables → Actions برو و این Secretها را اضافه کن:
   - `TELEGRAM_BOT_TOKEN`: توکن ربات
   - `TELEGRAM_CHAT_ID`: شناسهٔ کانال یا `@channelusername`
3. ربات را به کانال مقصد اضافه کن و دسترسی انتشار پیام بده؛ برای آرشیو شخصی، `TELEGRAM_CHAT_ID` باید شناسهٔ همان کانال خصوصی باشد.
4. برای اعلان و لینک تماشا از `"mode": "links"` استفاده کن؛ برای دریافت فایل‌های مجاز، `"mode": "files"` را انتخاب کن و RSS/Atom را به آرایهٔ `feeds` اضافه کن.
5. در حالت فایل، RSS باید لینک مستقیم HTTPS به فایل ویدئویی داشته باشد و hostname همان فایل باید دقیقاً در `allowed_download_hosts` باشد؛ صفحهٔ تماشا، magnet و تورنت رد می‌شوند.
6. ابتدا `dry_run` را روی `true` نگه دار و اجرای دستی را بررسی کن. فقط پس از بررسی منبع، مجوز محتوا، سقف حجم و مقصد، متغیر `ANIMEHIGHBO_DRY_RUN` را روی `false` قرار بده.

توکن را در کد، فایل‌های مخزن یا پیام‌های عمومی قرار نده.

## ارسال فایل‌های بزرگ‌تر از ۵۰ مگابایت

حالت پیش‌فرض همچنان از Telegram Bot API ابری استفاده می‌کند و سقف دانلود فایل در تنظیمات روی ۴۵ مگابایت است. برای فایل‌های بزرگ‌تر، این پروژه یک حالت اختیاری برای سرور محلی Bot API دارد:

1. در GitHub → Settings → Secrets and variables → Actions این Secretها را اضافه کن:
   - `TELEGRAM_API_ID`
   - `TELEGRAM_API_HASH`
2. در بخش Variables یک متغیر به نام `TELEGRAM_LOCAL_API` با مقدار `true` بساز.
3. برای سقف ۱٫۸ گیگابایت، متغیر `ANIMEHIGHBO_MAX_FILE_SIZE_MB` را روی `1800` قرار بده.
4. حالت فایل را با `"mode": "files"`، یک فید مستقیم HTTPS از محتوایی که اجازهٔ بازنشرش را داری، و دامنهٔ همان فایل در `allowed_download_hosts` تنظیم کن.

این حالت از تصویر کانتینری جامعه‌محور `aiogram/telegram-bot-api` استفاده می‌کند که سرور متن‌باز Telegram Bot API را بسته‌بندی می‌کند؛ این تصویر، محصول رسمی تیم تلگرام نیست. حالت محلی به `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` نیاز دارد. این پروژه فقط برای ارسال پیام استفاده می‌کند و webhook یا دریافت update را پیکربندی نمی‌کند. اگر همین ربات جای دیگری update دریافت می‌کند، قبل از جابه‌جایی به سرور محلی، دستورالعمل رسمی انتقال تلگرام را بررسی کن.

Runner استاندارد GitHub Actions در مخزن عمومی رایگان است، اما فایل‌های ویدئویی روی runner موقت‌اند و پس از پایان اجرا باقی نمی‌مانند. سقف فایل، سرعت اینترنت، زمان اجرای workflow و فضای دیسک همچنان محدودیت‌های عملی‌اند؛ به همین دلیل موفقیت ارسال ۱٫۸ گیگابایتی باید با یک فایل مجاز واقعی آزمایش شود.

## زیرنویس دوزبانهٔ انگلیسی و فارسی

این قابلیت برای فایل‌های مجاز دارای زیرنویس انگلیسیِ متنی درون ویدئو است.

- با فعال‌بودن `bilingual_subtitles`، ابزار ترک انگلیسی را پیدا می‌کند، متن آن را استخراج می‌کند و زیرنویس فارسی را می‌سازد.
- اگر Secret به نام `GEMINI_API_KEY` تنظیم شده باشد، ترجمه و بازبینی با Gemini انجام می‌شود؛ در غیر این صورت مترجم آفلاین Argos استفاده می‌شود و ممکن است نیاز به بازبینی داشته باشد.
- خروجی MKV دو ترک قابل انتخاب دارد: English و فارسی. با فعال‌کردن `burn_persian_subtitles`، ترجمهٔ فارسی علاوه بر ترک انتخابی، روی تصویر نیز با رنگ زرد و حاشیهٔ مشکی بسیار نازک حک می‌شود.
- `burn_persian_subtitles` نیازمند فعال‌بودن `bilingual_subtitles` و `encode_h265` است.
- اگر زبان ترک انگلیسی در فایل درست ثبت نشده باشد، `subtitle_stream_index` را با شمارهٔ stream سراسری ffprobe تنظیم کن.
- فایل‌های `.en.srt` و `.fa.srt` برای بازبینی ساخته می‌شوند و پس از پایان اجرا از runner موقت پاک می‌شوند.

برای پردازش دستی یک فایل محلیِ مجاز:
```bash
python -m pip install -r requirements-subtitles.txt
python tools/bilingual_subtitles.py input.mkv --output output.bilingual.mkv
```

برای فشرده‌سازی H.265 به‌صورت مستقل از خط RSS:
```bash
sudo apt-get install ffmpeg fonts-noto-core
python -c "from pathlib import Path; from tools.video_encoder import encode_h265; encode_h265(Path('input.mkv'), Path('output.h265.mkv'), crf=24, preset='slow')"
```

## دانلود تورنت و Magnet برای محتوای مجاز

پشتیبانی اختیاری از `aria2` اضافه شده است، اما هیچ تورنتی به‌طور پیش‌فرض فعال نیست. وجود RSS یا لینک Magnet به‌تنهایی مجوز دانلود و بازنشر ایجاد نمی‌کند. فقط منابعی را وارد کن که مجوز دانلود، پردازش و انتشار فایلشان را داری.

در `config.json` (نه فایل نمونه) این فیلدها را تنظیم کن:
```json
{
  "allowed_torrent_hosts": ["torrents.example.org"],
  "torrent_timeout_seconds": 18000,
  "torrent_sources": [
    {
      "title": "Authorized Anime - 01 (1080p)",
      "uri": "magnet:?xt=urn:btih:REPLACE_WITH_REAL_INFO_HASH",
      "authorized_for_redistribution": true
    }
  ]
}
```
برای فایل `.torrent`، مقدار `uri` باید HTTPS باشد و hostname آن دقیقاً در `allowed_torrent_hosts` قرار بگیرد. برای Magnet، URI باید دارای `xt=urn:btih:` باشد. فقط مواردی که مقدار `authorized_for_redistribution` آن‌ها دقیقاً `true` باشد پردازش می‌شوند. عنوان باید شامل کیفیت باشد تا ترتیب 1080p، سپس 720p و 480p درست عمل کند. Workflow، `aria2` را فقط وقتی دست‌کم یک منبع تورنت مجاز در تنظیمات وجود داشته باشد نصب می‌کند.

دانلود محدودیت زمان و حجم دارد، خروجی ویدئویی و امضای فایل بررسی می‌شود و فایل موقت تورنت پس از انتخاب ویدئو پاک می‌شود. این قابلیت در CI با آزمون‌های اعتبارسنجی آزمایش می‌شود؛ دانلود واقعی و ارسال تلگرام هنوز نیازمند یک تورنت قانونیِ قابل دسترس و اجرای واقعی workflow است. منابع SubsPlease/Nyaa در تنظیمات فعال نشده‌اند.

## مجوز محتوا

این پروژه برای فایل‌های عمومیِ مجاز، محتوای دارای مجوز بازنشر، یا فایل‌هایی که صاحب حق نشر اجازهٔ انتشارشان را داده است طراحی می‌شود. برای منابعی مانند SubsPlease و Nyaa.si، ربات برای دانلود و بازنشر قسمت‌های دارای حق نشر پیکربندی نشده است. اتصال SubsPlease صرفاً برای اعلان انتشار و اطلاعات/پوستر انیمه است؛ برای دانلود یا بازنشر ویدئو باید مجوز معتبر داشته باشید.


## راه‌اندازی RSS برای پردازش خودکار فایل

فایل تنظیمات اصلی `config.json` است. نمونهٔ کامل را در `config.example.json` ببین. برای افزودن منبع، آرایهٔ `feeds` را با RSS/Atom واقعیِ ناشری که دانلود فایل را مجاز کرده پر کن و `allowed_download_hosts` را دقیقاً با hostname لینک مستقیم فایل ویدئو تنظیم کن. wildcard و دامنهٔ کلی پذیرفته نمی‌شود.

نمونهٔ ساختار فید:
```json
{
  "name": "Authorized anime source",
  "url": "https://media.example.org/feed.xml"
}
```

فید باید در هر آیتم، لینک مستقیم HTTPS به فایل ویدئویی با پسوند `.mkv`، `.mp4`، `.webm` یا `.mov` را در RSS enclosure یا Atom link با `rel="enclosure"` داشته باشد. اگر RSS فقط به صفحهٔ تماشا، صفحهٔ معرفی، لینک تورنت یا magnet اشاره کند، دانلودکننده آن را رد می‌کند. دامنهٔ RSS و دامنهٔ فایل می‌توانند متفاوت باشند؛ فقط دامنهٔ دقیق فایل در `allowed_download_hosts` قرار می‌گیرد. فیدها باید فقط برای محتوایی استفاده شوند که اجازهٔ دریافت و پردازش آن را داری.

برای فعال‌کردن خط پردازش فایل، تنظیمات اصلی باید شبیه این باشد:
- `"mode": "files"`
- `"bilingual_subtitles": true` برای استخراج زیرنویس انگلیسی و افزودن ترک فارسی
- `"encode_h265": true` برای تبدیل به H.265؛ مقدار پیش‌فرض نمونه `h265_crf: 24` و `h265_preset: "slow"` است
- `"burn_persian_subtitles": true` برای حک‌کردن ترجمهٔ فارسی با رنگ زرد و حاشیهٔ مشکی نازک؛ این گزینه به دو گزینهٔ بالا نیاز دارد
- `"dry_run": true` را برای اولین اجرا حفظ کن. پس از تأیید فید، مجوز محتوا، حجم خروجی و مقصد، متغیر `ANIMEHIGHBO_DRY_RUN` را روی `false` بگذار تا ارسال زنده انجام شود.

برای ترجمهٔ باکیفیت‌تر، Secretهای `GEMINI_API_KEY`، `GEMINI_API_KEY_2`، `GEMINI_API_KEY_3` و `GEMINI_API_KEY_4` را در GitHub Actions اضافه کن؛ `GEMINI_API_KEY_1` نیز اختیاری است. ابزار هنگام خطای سهمیه یا دسترسی کلید، کلید بعدی را امتحان می‌کند و هیچ‌وقت ترجمهٔ ناقص را معتبر نمی‌داند. مدل از `GEMINI_MODEL` خوانده می‌شود و اگر تعیین نشود `gemini-3.5-flash-lite` استفاده می‌شود. محدودیت سهمیه ممکن است در سطح پروژه یا حساب اعمال شود؛ چند کلید لزوماً سهمیهٔ تجمیعی بیشتری ایجاد نمی‌کنند. بدون هیچ کلیدی، ابزار به مترجم آفلاین Argos برمی‌گردد که ممکن است به بازبینی انسانی نیاز داشته باشد.

Workflow انتشار هر ۳۰ دقیقه RSSها را بررسی می‌کند و اجرای دستی هم در GitHub Actions موجود است. برای هر قسمت، ابتدا پوستر و خلاصهٔ فارسی منتشر می‌شود؛ سپس فایل‌ها به ترتیب 1080p، 720p و 480p و تک‌به‌تک پردازش و ارسال می‌شوند. نام فایل نمونه `PSYREN 1080p @Animehighbo.mkv` است. فایل‌های موقت پس از هر ارسال پاک می‌شوند؛ سابقهٔ ارسال و پوستر در `data/state.json` ذخیره می‌شود. برای فایل‌های بزرگ‌تر از سقف Bot API ابری، حالت Telegram Local Bot API را فعال کن و `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` را به‌عنوان Secrets قرار بده. تنظیمات `TELEGRAM_LOCAL_API` و `ANIMEHIGHBO_MAX_FILE_SIZE_MB` از Variables یا Secrets خوانده می‌شوند.

نکتهٔ کیفیت: CRF پایین‌تر معمولاً کیفیت بالاتر و حجم بیشتر می‌دهد. `CRF 24 + preset slow` نقطهٔ شروع است، نه تضمین حجم یا کیفیت ثابت برای تمام فایل‌ها. خروجی قبل از ارسال با ffprobe بررسی می‌شود؛ اگر فایل خراب باشد، مدت‌زمان به‌شدت تغییر کند یا ترک صدا/زیرنویس از بین برود، انتشار متوقف می‌شود.

## افزودن خودکار RSS از فایل RSS input

برای افزودن یا تغییر RSSها لازم نیست مستقیماً `config.json` را ویرایش کنی:

1. فایل [`RSS input.txt`](RSS%20input.txt) را در ریشهٔ مخزن باز کن.
2. هر نشانی کامل HTTPS مربوط به RSS/Atom را در یک خط جداگانه قرار بده. خط‌های خالی و خط‌هایی که با `#` شروع می‌شوند نادیده گرفته می‌شوند.
3. تغییرات را در شاخهٔ `main` ذخیره کن. GitHub Actions فایل را بررسی می‌کند و آرایهٔ `feeds` در `config.json` را خودکار به‌روزرسانی و commit می‌کند.
4. تنظیمات دیگر `config.json`، از جمله حالت آزمایشی، فشرده‌سازی، زیرنویس‌ها و سقف حجم، حفظ می‌شوند. URLهای تکراری حذف می‌شوند؛ URL نامعتبر یا غیر HTTPS باعث شکست بررسی می‌شود.

**مهم:** این فایل فقط فهرست `feeds` را تنظیم می‌کند. برای حالت دانلود ویدئو، RSS باید لینک مستقیم HTTPS فایل ویدئوییِ مجاز برای بازنشر داشته باشد. دامنهٔ فایل‌های ویدئویی را جداگانه و آگاهانه در `allowed_download_hosts` قرار بده؛ دامنهٔ خود RSS ممکن است با دامنهٔ فایل‌ها فرق داشته باشد و ربات عمداً آن را خودکار مجاز نمی‌کند. افزودن RSS به‌تنهایی مجوز دانلود یا بازنشر ایجاد نمی‌کند. حالت `dry_run` نیز تغییر نمی‌کند.

## آرشیو ترتیبی قسمت‌ها (قابلیت جدید)

پشتیبانی از صف آرشیو در شاخهٔ `feature/episode-archive-backfill` پیاده‌سازی شده است؛ تا زمانی که صف منبع معتبر تکمیل و آزمایش انتهابه‌انتها انجام نشده، این قابلیت به‌صورت پیش‌فرض خاموش است و نباید آن را انتشار کامل آرشیو تلقی کرد.

- `archive_mode`: فعال‌سازی صف آرشیو به‌جای RSSهای لحظه‌ای.
- `archive_manifest`: مسیر فهرست مرتب‌شده، پیش‌فرض `data/archive_manifest.json`.
- هر ردیف باید عنوان تک‌قسمتی، URI منبع و مقدار صریح `"authorized_for_redistribution": true` داشته باشد.
- ترتیب ردیف‌ها ترتیب پردازش است. ورودی‌های بدون شمارهٔ قسمت، عنوان‌های batch و URIهای تکراری رد می‌شوند.
- در حالت آرشیو، RSS و منابع تورنت ایستا نادیده گرفته می‌شوند تا قسمت‌های تازه یا خارج از ترتیب از صف جلو نزنند.
- فایل `data/archive_manifest.json` فعلاً خالی است (`[]`). فید SubsPlease فعلی فهرست کامل تاریخی قسمت‌ها را فراهم نمی‌کند؛ بنابراین آرشیو تاریخی هنوز آمادهٔ انتشار نیست.

برای ساختن صف از کاتالوگ SubsPlease، گردش‌کار `Build authorized episode archive catalog` در GitHub Actions اضافه شده است. این گردش‌کار با تاریخ پیش‌فرض `2026-09-01`، قسمت‌های منتشرشده از آن تاریخ را پیدا می‌کند؛ اگر قسمت ۱ یک سری در همین بازه منتشر شده باشد، صف از قسمت ۱ تا آخرین قسمت موجود ساخته می‌شود، اما برای سری‌های قدیمی‌تر فقط قسمت‌هایی که تاریخ انتشارشان در این بازه است انتخاب می‌شوند. تنها Magnetهای 1080p یا 720p پذیرفته می‌شوند؛ سری‌های دارای شمارهٔ قسمتِ جاافتاده یا منبع مناسبِ مفقود از صف کنار گذاشته می‌شوند. پس از تولید، manifest در شاخهٔ همین PR commit و به‌عنوان artifact هفت‌روزه نگهداری می‌شود. این مرحله فقط صف را می‌سازد و به‌تنهایی چیزی در کانال منتشر نمی‌کند.

برای اجرای محلی، پس از نصب `requirements.txt`:
```bash
python tools/archive_catalog.py --since 2026-09-01 --max-pages 100 --output data/archive_manifest.json --confirm-redistribution-rights
```

پرچم `--confirm-redistribution-rights` اجباری است و تأیید می‌کند که برای تمام فایل‌های انتخاب‌شده مجوز دانلود، پردازش و بازنشر وجود دارد. صف باید قبل از روشن‌کردن `archive_mode` از نظر منابع و ترتیب بررسی شود.

نمونهٔ ساختار ورودی مجاز:
```json
[
  {
    "title": "Authorized Series - 01 (1080p)",
    "uri": "https://media.example.org/authorized-episode-01.mkv",
    "authorized_for_redistribution": true
  },
  {
    "title": "Authorized Series - 02 (1080p)",
    "uri": "https://media.example.org/authorized-episode-02.mkv",
    "authorized_for_redistribution": true
  }
]
```

این نمونه صرفاً ساختار داده است و نشانی‌های `example.org` فایل واقعی نیستند. برای لینک مستقیم HTTPS ویدئو، hostname دقیق آن باید در `allowed_download_hosts` باشد؛ برای لینک Magnet یا فایل `.torrent`، تنظیمات `allowed_torrent_hosts` و محدودیت‌های downloader باید با منبع واقعی سازگار باشند. لینک‌های مستقیم ویدئو از downloader فایل و Magnet/تورنت از downloader تورنت عبور می‌کنند. پیش از فعال‌کردن آرشیو باید تمام ردیف‌ها به منابع واقعی و مجاز، قابل‌دسترسی و دارای ویدئوی تکی نگاشت شوند. پس از آن باید اجرای آزمایشی، اعتبارسنجی فایل‌ها و زیرنویس‌ها، و ارسال کنترل‌شده به کانال بررسی شود. هر قسمت باید پوستر داشته باشد و سپس سه کیفیت 1080p، 720p و 480p به همان پوستر پاسخ داده شوند؛ در صورت شکست، انتشار قسمت بعدی متوقف می‌شود.

## وضعیت تحویل و انتشار

- آزمون‌های اعتبارسنجی صف آرشیو به مجموعهٔ تست اضافه شده‌اند.
- تغییرات در [درخواست ادغام شمارهٔ ۱۶](https://github.com/studio1111/Animehighbo/pull/16) قرار دارند و هنوز ادغام نشده‌اند.
- تا وقتی `data/archive_manifest.json` از فهرست واقعیِ دارای مجوز پر نشده و اجرای زنده موفق ثبت نشده، دانلود آرشیو، ساخت همهٔ خروجی‌ها و انتشار کامل در کانال تأییدشده محسوب نمی‌شود.
- اطلاعات ورود و کلیدهای API باید فقط در GitHub Actions Secrets بمانند؛ هیچ کلیدی را در manifest یا README قرار نده.
