# Animehighbo

ربات زمان‌بندی‌شدهٔ **Animehighbo** برای تلگرام: پایش فیدهای مجاز، دریافت فایل‌هایی که اجازهٔ دانلود و بازنشرشان را دارید، جلوگیری از انتشار تکراری و ارسال فایل به کانال تلگرام.

## وضعیت فعلی

پایش RSS منبع SubsPlease به‌صورت جداگانه برای کیفیت‌های 720p و 1080p فعال است. این پایش فقط عنوان انتشار را می‌خواند، پوستر و اطلاعات انیمه را از AniList می‌گیرد و پیام فارسیِ همراه پوستر می‌سازد؛ لینک magnet یا فایل ویدئویی دانلود یا بازنشر نمی‌شود. فید 480p در بررسی زنده محتوای RSS برنگرداند، بنابراین فعال نشده است. بخش ناشر فایل همچنان فقط برای منابع و فایل‌هایی است که مجوز انتشارشان را دارید.

## قابلیت‌ها

- پایش SubsPlease برای فیدهای زندهٔ 720p و 1080p هر ۳۰ دقیقه با GitHub Actions و اجرای دستی
- ساخت پست فارسی همراه پوستر و اطلاعات AniList برای انتشارهای جدید، با جلوگیری از تکرار و بدون ارسال لینک‌های magnet
- حالت لینک‌محور برای انتشار پوستر، نام انیمه، شمارهٔ قسمتِ قابل استخراج و دکمهٔ لینک تماشا
- دریافت پوستر از RSS/Atom یا فراداده‌های Open Graph صفحهٔ قسمت، با سقف ۸ مگابایت
- خواندن RSS/Atom از منابع مجاز
- کنترل شناسه و هش فایل برای جلوگیری از تکرار
- دریافت فایل مستقیم فقط از دامنه‌های HTTPS مجاز پیکربندی‌شده
- کنترل حجم و امضای ابتدایی فایل پیش از ارسال
- تبدیل اختیاری ویدئو به H.265/HEVC در MKV با کنترل CRF و preset، بررسی مدت‌زمان/کدک/ترک‌ها و امکان حک‌کردن زیرنویس فارسی زرد با حاشیهٔ مشکی نازک\n- ارسال MP4 با Telegram Bot API به روش sendVideo
- ارسال MKV و سایر فرمت‌های پشتیبانی‌شده به روش sendDocument
- استخراج زیرنویس انگلیسیِ متنی، ترجمه با Gemini در صورت تنظیم `GEMINI_API_KEY` (و در غیر این صورت مترجم آفلاین Argos)، و نگهداری هر دو ترک در MKV
- پشتیبانی از نشانی قابل تنظیم Telegram Bot API برای سرور محلی
- نگهداری وضعیت انتشار برای جلوگیری از تکرار در اجراهای بعدی
- آزمون‌های خودکار

## راه‌اندازی

1. با BotFather یک ربات تلگرام بساز.
2. در مخزن GitHub به Settings → Secrets and variables → Actions برو و این Secretها را اضافه کن:
   - `TELEGRAM_BOT_TOKEN`: توکن ربات
   - `TELEGRAM_CHAT_ID`: شناسهٔ کانال یا `@channelusername`
3. ربات را به کانال Animehighbo اضافه کن و دسترسی انتشار پیام بده.
4. فایل `config.json` را با `"mode": "links"` و نشانی HTTPS فید RSS/Atom منبع قسمت‌ها تکمیل کن. مقدار `feeds` در نسخهٔ اصلی خالی است؛ تا وقتی منبع واقعی اضافه نشود، چیزی منتشر نمی‌شود. نشانی نمونه در `config.example.json` فقط جای‌نگهدار است.
5. ربات از عنوان فید شمارهٔ قسمت را استخراج می‌کند؛ اگر شماره در عنوان یا داده‌های منبع نباشد، به‌جای حدس‌زدن اعلام می‌کند که شماره مشخص نیست.
6. متغیر مخزن `ANIMEHIGHBO_DRY_RUN` را ابتدا روی `true` قرار بده و اجرای دستی را بررسی کن. فقط پس از بررسی مقصد، مجوز محتوا و تنظیمات، آن را روی `false` قرار بده.

توکن را در کد، فایل‌های مخزن یا پیام‌های عمومی قرار نده.

## ارسال فایل‌های بزرگ‌تر از ۵۰ مگابایت

حالت پیش‌فرض همچنان از Telegram Bot API ابری استفاده می‌کند و سقف دانلود فایل در تنظیمات روی ۴۵ مگابایت است. برای فایل‌های بزرگ‌تر، این پروژه یک حالت اختیاری برای سرور محلی Bot API دارد:

1. در GitHub → Settings → Secrets and variables → Actions این Secretها را اضافه کن:
   - `TELEGRAM_API_ID`
   - `TELEGRAM_API_HASH`
2. در بخش Variables یک متغیر به نام `TELEGRAM_LOCAL_API` با مقدار `true` بساز.
3. برای سقف ۱٫۸ گیگابایت، متغیر `ANIMEHIGHBO_MAX_FILE_SIZE_MB` را روی `1800` قرار بده.
4. حالت فایل را با `"mode": "files"`، یک فید مستقیم HTTPS از محتوایی که اجازهٔ بازنشرش را داری، و دامنهٔ همان فایل در `allowed_download_hosts` تنظیم کن.

این حالت از تصویر کانتینری جامعه‌محور `aiogram/telegram-bot-api` استفاده می‌کند که سرور متن‌باز Telegram Bot API را بسته‌بندی می‌کند؛ این تصویر، محصول رسمی تیم تلگرام نیست. حالت محلی به `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` نیاز دارد. این پروژه فقط برای ارسال پیام استفاده می‌کند و webhook یا دریافت update را پیکربندی نمی‌کند. اگر همین ربات جای دیگری update دریافت می‌کند، قبل از جابه‌جایی به سرور محلی، دستورالعمل رسمی انتقال تلگرام را بررسی کن.

Runner استاندارد GitHub Actions در مخزن عمومی رایگان است، اما فایل‌های ویدئویی روی runner موقت‌اند و پس از پایان اجرا باقی نمی‌مانند. سقف فایل، سرعت اینترنت، زمان اجرای workflow و فضای دیسک همچنان محدودیت‌های عملی‌اند؛ به همین دلیل موفقیت ارسال ۱٫۸ گیگابایتی باید با یک فایل مجاز واقعی آزمایش شود.

## زیرنویس دوزبانهٔ انگلیسی و فارسی

این قابلیت اختیاری است و برای فایل‌هایی است که از قبل روی فید مستقیم مجاز قرار دارند و زیرنویس انگلیسیِ متنی درون ویدیو دارند.

- در `config.json` مقدار `mode` را روی `files` و `bilingual_subtitles` را روی `true` قرار بده.
- در حالت خودکار، ابزار ترک زیرنویسی را که زبان آن `eng` یا `en` ثبت شده باشد انتخاب می‌کند. اگر زبان در فایل درست ثبت نشده، `subtitle_stream_index` را با شمارهٔ stream سراسری ffprobe تنظیم کن.
- GitHub Actions در صورت فعال‌بودن این گزینه، FFmpeg و وابستگی ترجمهٔ آفلاین رایگان Argos Translate را نصب می‌کند.
- خروجی MKV شامل دو ترک قابل انتخاب است: English و فارسی. این دو ترک به‌طور هم‌زمان روی تصویر چسبانده نمی‌شوند؛ بین آن‌ها از پخش‌کننده انتخاب می‌کنی.
- فایل‌های `.en.srt` و `.fa.srt` نیز برای بازبینی کنار خروجی ساخته می‌شوند و سپس از runner موقت پاک می‌شوند.
- ترجمه با مدل آفلاین انجام می‌شود و ممکن است اصطلاحات، شوخی‌ها، نام‌ها و لحن محاوره‌ای را دقیق منتقل نکند. این یک پیش‌نویس رایگان است و کیفیت «ترجمهٔ انسانیِ روان» را تضمین نمی‌کند؛ قبل از بازنشر باید بازبینی شود.

برای پردازش دستی یک فایل محلیِ مجاز:
```bash
python -m pip install -r requirements-subtitles.txt
python tools/bilingual_subtitles.py input.mkv --output output.bilingual.mkv
```

اگر چند ترک زیرنویس وجود داشته باشد، ابزار ابتدا با برچسب زبان انگلیسی را پیدا می‌کند. برای انتخاب دستی، از `--subtitle-stream INDEX` استفاده کن.

## مجوز محتوا

این پروژه برای فایل‌های عمومیِ مجاز، محتوای دارای مجوز بازنشر، یا فایل‌هایی که صاحب حق نشر اجازهٔ انتشارشان را داده است طراحی می‌شود. برای منابعی مانند SubsPlease و Nyaa.si، ربات برای دانلود و بازنشر قسمت‌های دارای حق نشر پیکربندی نشده است. اتصال SubsPlease صرفاً برای اعلان انتشار و اطلاعات/پوستر انیمه است؛ برای دانلود یا بازنشر ویدئو باید مجوز معتبر داشته باشید.


## راه‌اندازی RSS برای پردازش خودکار فایل

فایل تنظیمات اصلی `config.json` است. نمونهٔ کامل را در `config.example.json` ببین. برای افزودن منبع، آرایهٔ `feeds` را با RSS/Atom واقعیِ ناشری که دانلود فایل را مجاز کرده پر کن و `allowed_download_hosts` را دقیقاً با hostname لینک مستقیم فایل ویدئو تنظیم کن. wildcard و دامنهٔ کلی پذیرفته نمی‌شود.

نمونهٔ ساختار فید:
```json
{
  "name": "Authorized anime source",
  "url": "https://media.example.org/feed.xml"
}
```

فید باید در هر آیتم، لینک مستقیم HTTPS به فایل ویدئویی با پسوند `.mkv`، `.mp4`، `.webm` یا `.mov` را در RSS enclosure یا Atom link با `rel="enclosure"` داشته باشد. اگر RSS فقط به صفحهٔ تماشا، صفحهٔ معرفی، لینک تورنت یا magnet اشاره کند، دانلودکننده آن را رد می‌کند. دامنهٔ RSS و دامنهٔ فایل می‌توانند متفاوت باشند؛ فقط دامنهٔ دقیق فایل در `allowed_download_hosts` قرار می‌گیرد. فیدها باید فقط برای محتوایی استفاده شوند که اجازهٔ دریافت و پردازش آن را داری.

برای فعال‌کردن خط پردازش فایل، تنظیمات اصلی باید شبیه این باشد:
- `"mode": "files"`
- `"bilingual_subtitles": true` برای استخراج زیرنویس انگلیسی و افزودن ترک فارسی
- `"encode_h265": true` برای تبدیل به H.265؛ مقدار پیش‌فرض نمونه `h265_crf: 24` و `h265_preset: "slow"` است
- `"burn_persian_subtitles": true` برای حک‌کردن ترجمهٔ فارسی با رنگ زرد و حاشیهٔ مشکی نازک؛ این گزینه به دو گزینهٔ بالا نیاز دارد
- `"dry_run": true` را برای اولین اجرا حفظ کن. پس از تأیید فید، مجوز محتوا، حجم خروجی و مقصد، متغیر `ANIMEHIGHBO_DRY_RUN` را روی `false` بگذار تا ارسال زنده انجام شود.

برای ترجمهٔ باکیفیت‌تر، Secret به نام `GEMINI_API_KEY` را در GitHub Actions اضافه کن؛ مدل از `GEMINI_MODEL` خوانده می‌شود و اگر تعیین نشود `gemini-3.5-flash-lite` استفاده می‌شود. بدون کلید، ابزار به مترجم آفلاین Argos برمی‌گردد که ممکن است به بازبینی انسانی نیاز داشته باشد.

Workflow انتشار هر ۳۰ دقیقه RSSها را بررسی می‌کند و اجرای دستی هم در GitHub Actions موجود است. فایل‌ها در runner موقت پردازش و پس از ارسال پاک می‌شوند؛ سابقهٔ ارسال در `data/state.json` ذخیره می‌شود. برای فایل‌های بزرگ‌تر از سقف Bot API ابری، حالت Telegram Local Bot API را فعال کن و `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` را به‌عنوان Secrets قرار بده. تنظیمات `TELEGRAM_LOCAL_API` و `ANIMEHIGHBO_MAX_FILE_SIZE_MB` از Variables یا Secrets خوانده می‌شوند.

نکتهٔ کیفیت: CRF پایین‌تر معمولاً کیفیت بالاتر و حجم بیشتر می‌دهد. `CRF 24 + preset slow` نقطهٔ شروع است، نه تضمین حجم یا کیفیت ثابت برای تمام فایل‌ها. خروجی قبل از ارسال با ffprobe بررسی می‌شود؛ اگر فایل خراب باشد، مدت‌زمان به‌شدت تغییر کند یا ترک صدا/زیرنویس از بین برود، انتشار متوقف می‌شود.
